# Tool Bridge Mobile 整体架构

## 产品定位

`tool-bridge-mobile` 是 HTBP / Tool Bridge 生态的移动设备运行时，基于 React Native 与 Expo
development build 面向 Android 和 iOS。它让 Agent 在用户明确授权、系统权限和平台限制之内调用手机能力，
不是远程桌面、监控软件、MDM 或任意第三方 App UI 自动化工具。

代码、HTBP 正式规范和 Tool Bridge 已发布 API 是事实真源；`llmdoc/` 只保存跨任务复用的高密度知识。
设计文档、历史验证记录与实现冲突时，应先核实代码和正式契约，再同步知识面，不能把目标态或示例写成
当前 SDK 可运行事实。

## 仓库边界

本仓库拥有移动 App、移动端运行时、本地策略与确认、安全存储、SQLite 持久化、UI 和必要的 Kotlin/Swift
原生模块。主要区域是：

- `app/`、`src/ui/`：Expo Router 页面、全局确认、前台相机、媒体控制、本地信箱、Activity 和设置界面；
- `src/runtime/`、`src/policy/`：应用生命周期、唯一命令执行入口、本地撤销、确认和裁决；
- `src/gateway/`、`src/identity/`：官方 device SDK transport、Gateway 配置和 SecureStore 身份/凭证；
- `src/storage/`、`src/inbox/`：command/audit/timer/inbox 数据域、幂等、保留和内容处理；
- `src/capabilities/`、`modules/`：类型化设备能力及必要的 Expo 原生模块；
- `test/contract/`：本地执行边界的注入式契约测试，不是 Gateway wire 或真机端到端测试。

本仓库不拥有 HTBP 通用协议、Tool Bridge Gateway、跨运行时公共 SDK、服务端异步 command mailbox、push
registration/dispatch、动态 capability profile、对象存储或浏览器扩展；只拥有正式 SDK mailbox API 的
移动 consumer wiring 与 installation-local operation journal。缺失的通用能力必须在上游交付，不能复制
`@tool-bridge/core` 私有源码建立长期分叉。

## 整体数据流

```text
官方 SDK realtime device call / durable mailbox claim / 本地测试 dispatcher
  -> transport adapter 归一化 command
  -> mailbox 路径先持久化 operation execution barrier
  -> LocalCommandExecutor
  -> schema / deadline / cancellation / admission / live probe / policy / confirmation
  -> SQLite claim 与防重放
  -> 类型化 capability handler / 平台 adapter
  -> output schema 与字节上限
  -> persistent outcome + redacted audit
  -> SDK result 与本地 UI snapshot
```

Transport 不能越过本地安全执行链。系统权限、用户拒绝、实时 capability probe、前后台/锁屏条件、
deadline/cancel、逐次确认和 emergency disable 始终高于远程命令或 Gateway 许可。凭证材料只进入系统安全
存储；普通审计不记录位置、照片、消息正文、完整 URL 或其他敏感载荷。

## 现状

- P0 本地安全运行时、官方 `@tool-bridge/sdk/device@0.21.0` realtime 与 durable mailbox consumer wiring、
  手工 Gateway HTTPS origin/API key 内测入口和若干能力纵向切片已经实现。
- `phone/camera.capture_photo` 已形成仅前台的本地纵向切片：非 Direct 模式由用户拍摄并复核，Direct call
  仍展示可见预览但在相机就绪后自动拍摄；处理后的 JPEG 通过 0.17 首次交付、当前 0.21.0 继续提供的
  每次调用 Store capability 上传，成功结果只返回稳定 `store://default/...` URI 与脱敏元数据。缺少该
  capability 时会在确认和相机 probe 前 fail closed。
- 只有 SDK `ready` 可投影为 online；手工长期 API key 不等于 pairing credential，也不证明真实 Gateway
  的完整兼容矩阵。
- `phone/inbox.deliver` 声明 `delivery: both`：既可 realtime 直调，也可由官方 processor 在 App 初始化/
  配置完成且 active 或回到 active 时显式有界 drain。SQLite v5 operation journal 让 executing crash
  保守恢复为 `result_unknown`；它没有 timer 驱动的新 drain、后台轮询或 push 唤醒，不提供后台必达或
  最终送达语义。
- Android 已有一次 SDK 0.17 Preview 后置相机 Direct call 完成拍摄、Store 上传、stat 和受保护回读校验；
  该日期化证据不能外推到 iOS、其他镜头/权限状态、后台/弱网、长期稳定性或 pairing。
- 当前仍未达到 MVP；pairing、credential 生命周期 binding、动态 profile、U-5 真实 Gateway/双端联合验收、
  U-6 push、通用受保护对象读取与完整 U-7、真实 Gateway/storage 兼容矩阵、完整双端构建/真机矩阵与
  production 发布证据仍未完成。

## 已决定

- 系统权限、用户拒绝、设备状态和平台限制高于远程命令，高风险能力默认拒绝或逐次确认。
- 每个公开能力必须声明 effect、risk、confirmation、前后台条件、queue policy、平台支持和 live probe；
  不能仅凭 OS 名称推断可用。
- 未来 trusted grant 绑定已认证 Gateway Credential 实例及其 audience/identity/generation，不绑定具体
  Agent；该方向已决定但尚未实现，详见 `integration/trusted-grants.mdx`。
- 通用逻辑优先 TypeScript；平台 API 优先成熟 Expo 模块，必要时才使用 Expo Modules API。
- 包管理器使用仓库锁定的 pnpm；Expo Go 不是验收环境。

## 未实现与未验证

上游 U-2/U-3/U-4/U-6、U-5 剩余联合验收、完整 U-7、真实 Gateway 能力矩阵、iOS 原生/真机、双端权限/
后台/锁屏、production signing、商店合规、rollout 与 rollback 都必须保持明确的“未实现”或“未验证”
标签。历史日期化快照不作为 V3 持续事实；证据应按 `delivery/verification-evidence.mdx` 回到对应
commit/artifact 和当前命令结果。

## 主题路由

- `runtime/`：本地命令执行、策略、持久化、清除、恢复、安全和 accessibility；
- `capabilities/`：当前能力总览，以及 camera、media、Linking、inbox、notification、timer 的稳定契约；
- `integration/`：SDK transport、手工 Gateway、trusted grant 决策和上游/平台缺口；
- `product/`：稳定产品需求、非目标、质量目标与 P0-P3 路线；
- `delivery/`：工程基线、DOD、证据语言、验证、EAS 项目绑定和 GitHub Preview 发布。
