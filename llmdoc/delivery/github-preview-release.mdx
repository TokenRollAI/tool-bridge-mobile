# GitHub Preview 发布

## 定位

仓库有两条收敛到同一内部 GitHub Pre-release 的路径：

- `.github/workflows/auto-release.yml` 在 `main` 的 `verify` push run 成功后，确认 verified SHA 仍是最新
  `main`，从 App version 派生 tag，复用该 run 的 APK artifact，并在无冲突时创建 annotated tag/Release；
- `.github/workflows/release.yml` 接受 `vX.Y.Z` tag push，也提供必填 `release_tag` 的
  `workflow_dispatch`，重新 checkout 不可移动的既有 tag、执行验证与双端 build，并发布或修复 Release。

两条路径都交付不依赖 Metro 的 Android Preview APK 和 SHA-256，以 iOS simulator build 作为共同代码/
原生配置门禁；都不是 production/store release。

## 版本不变量

- tag：`vX.Y.Z`；
- package version：`X.Y.Z`；
- `app.config.ts` 的 `APP_VERSION`：`X.Y.Z`；
- `scripts/verify-app-config.mjs` 的 `releaseMetadata`：version 为 `X.Y.Z`，Android/iOS build number 与
  `app.config.ts` 完全一致；
- `CHANGELOG.md` 首个版本段：`## [X.Y.Z] - YYYY-MM-DD`，且正文非空；
- Android `versionCode` 与 iOS `buildNumber` 显式维护，发版时不得倒退。

`pnpm verify:release-tag` 在普通 verify 中检查 package/App version 与 latest changelog；传入 tag 时再检查
实际 tag 完全一致，`--notes` 只提取首个版本段供 GitHub Release 使用。不要让脚本自行读取通用
`GITHUB_REF_NAME`，因为 branch/PR workflow 同样设置该变量。

## 发布顺序

1. 同步 package、App、平台 build number与 `CHANGELOG.md` 最新版本段，在功能分支运行 frozen install、
   `pnpm verify`、peer check 与 dependency audit；
2. 合并到 `main` 后，`verify` 从 clean checkout 产出以 verified SHA 命名的 Preview APK artifact，并完成
   iOS simulator gate；
3. 自动路径只处理成功的 `main` push run，并在 prepare 与实际创建 tag 前两次确认 verified SHA 仍为远端
   `main` HEAD，避免连续 main push 之间的 TOCTOU；目标 tag 只要已经存在就幂等跳过，绝不移动、复用或
   用新 main artifact 补发旧 tag；
4. tag 尚不存在时，自动路径复用已验证 run 的 APK、重算版本化资产 SHA-256、创建指向 verified SHA 的
   annotated tag 并发布；若准备与发布之间 tag 被其他流程占用，也安全退出并交给 tag workflow；
5. 已有 tag 缺少 Release 时，以 `.github/workflows/release.yml` 的 `workflow_dispatch(release_tag)` 恢复：
   它精确 checkout 该 tag、验证 tag commit 可从 main 到达，重新运行 verify、Android Preview 与 iOS
   simulator 后创建 Release；如 Release 已存在，则覆盖上传同名资产并刷新 title/notes/prerelease 状态；
6. 下载 Release 的 APK 与 `.sha256`，独立核对 digest，并记录路径、workflow run、verified/tag commit 和
   asset URL。

验证/build job 只需只读权限；自动 prepare 只读 actions/contents，只有 publish job 使用
`contents: write`，并仅为下载已验证 artifact 增加 `actions: read`。仓库不得保存 GitHub token、keystore、
Apple certificate/profile 或 Gateway credential。

## 证据边界

GitHub Preview 成功只证明指定 tag 可从 clean checkout 通过仓库自动门禁并产出可追溯内部 APK。它不证明：

- production signer、AAB、IPA、商店提交或 staged rollout；
- APK/iOS 在物理设备完成权限、后台、锁屏、弱网与能力矩阵；
- 手工 Gateway URL/API key 已通过真实服务兼容验证；
- pairing、短期 ticket、mailbox、push 或服务端 revoke 已实现。

证据按 `delivery/verification-evidence.mdx` 记录；latest changelog 与 Release notes 必须继续写清以上边界。
